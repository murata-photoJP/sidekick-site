このタスクで扱う更新履歴は、ユーザーへ知らせる製品・サービスの変更だけです。
開発過程を記録するDevelopment Logとは分けてください。

更新候補は、`CHANGELOG_AI.md`、`PROJECT_STATUS.md`、`CURRENT_WORK.md`、
Gitコミット、Development LogのRelease Note候補、本番状態から調査してください。
内部修正を機械的にすべて掲載せず、利用者に意味がある変更だけを候補にしてください。

日本語と英語は必ず対で更新し、日付・項目数・事実関係を一致させてください。
生成済みHTMLだけを直接編集せず、テンプレートを正本としてビルドしてください。

私が「更新履歴の候補を確認して」と指示した場合は、前回掲載分以降を調査し、
掲載候補、掲載しない候補、その理由を提示してください。この時点ではファイルを変更しないでください。

私が候補を承認して「更新して」と指示したら、日英テンプレートと生成HTMLを更新し、
全テストと差分確認まで行ってください。コミット、プッシュ、デプロイはまだ行わないでください。

私が「確認した。デプロイして」と明示した場合だけ、今回の変更をコミットし、
`main`へプッシュしてVercel反映と日英の本番ページを確認してください。

最初の応答では、必要資料を参照できたか、Development Logとの違い、
日英同時更新、公開承認の境界を理解したかだけを報告してください。
この時点では更新履歴を変更しないでください。
